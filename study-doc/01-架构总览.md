# 01 — OpenClaw 架构总览

**版本**: 2026.5.28  
**技术栈**: TypeScript (主程序), Node.js v22+, pnpm monorepo  
**源码入口**: `openclaw.mjs` → `src/`

---

## 1. 一句话概括

> OpenClaw 是一个**以 Gateway 为中心、Plugin 为扩展、Agent 为核心**的个人 AI 助理网关。它接收来自各种聊天渠道的消息，通过 LLM Agent 处理，再把回复送回去。

## 4. 消息处理流程 (核心链路)

这是 OpenClaw 最核心的数据流：

```
用户消息 → Channel Plugin → Inbound Event
                                    ↓
                              Gateway Server (server-channels.ts)
                                    ↓
                          分类 + 路由 + 去重 + 防抖
                                    ↓
                        Session 分配/创建 (session-utils.ts)
                                    ↓
                        Agent 调度 (server-chat.ts)
                                    ↓
                    ┌─────────────────────────┐
                    │    Embedded Agent Runner  │
                    │  (embedded-agent-runner.ts)│
                    │                           │
                    │  1. 构建 System Prompt    │
                    │  2. 装配 Tool Context     │
                    │  3. 调用 LLM              │
                    │  4. 处理 Tool Calls       │
                    │  5. 流式输出 → 渠道       │
                    │  6. 持久化 Transcript     │
                    └─────────────────────────┘
                                    ↓
                             Compaction (压缩)
                                    ↓
                          回复送达渠道（出站桥）
```

**源文件映射**:
- Channel Inbound → `src/channels/message/receive.ts`, `src/channels/turn/kernel.ts`
- Session 分配 → `src/gateway/server-channels.ts`, `src/channels/session.ts`
- Agent 运行 → `src/agents/embedded-agent-runner.ts`, `src/agents/agent-command.ts`
- Tool 执行 → `src/agents/agent-tools.ts`, `src/agents/bash-tools.exec.ts`
- 输出送达 → `src/channels/message/send.ts`, `src/channels/message/outbound-bridge.ts`
- Compaction → `src/agents/compaction.ts`

## 5. 核心设计模式

### 5.1 Plugin 模式

OpenClaw 的一切功能几乎都是 Plugin。核心只提供网关和引擎，渠道/模型/工具/记忆全部是 Plugin。

**Plugin 类型**:
- **Code Plugin** — 运行时扩展（Provider、Channel、Hook、Tool）
- **Bundle Plugin** — 包静态资源（Skills、MCP 配置）

```
注册路径:
  Plugin Manifest → BundledPlugin 加载 → 激活 → 注册到 Registry
  源: src/plugins/bundled-sources.ts, src/plugins/registry.ts
```

### 5.2 Provider 模式

LLM 模型通过 Provider 抽象接入。每个 Provider 插件（Anthropic, OpenAI 等）实现标准接口，Gateway 统一调度。

```
Provider Runtime → Transport Stream → LLM Call
  源: src/agents/provider-transport-stream.ts, src/plugins/provider-runtime.ts
```

### 5.3 Channel 适配器模式

每种聊天渠道实现一套标准接口。Gateway 通过 Channel Plugin 统一处理消息的收发、媒体、状态。

```
Channel Plugin → Channel Contract → Registry
  源: extensions/discord/, extensions/telegram/, src/channels/plugins/
```

### 5.4 Agent 流水线模式

Agent 处理消息不是一步到位，而是经过多个阶段：

```
Bootstrap → 编译 System Prompt → LLM Call → Tool Calls → LLM Call → ... → Reply
         ↓                                                              ↓
    Context Cache                                                Transcript Persist
```

关键: `src/agents/embedded-agent-runner.ts` 中的 `runEmbeddedAgent()` 函数

### 5.5 Event/Subscription 模式

Gateway 内部事件广播（session 变更、agent 状态变化）通过订阅/通知模式实现。

```
server-broadcast.ts → 事件 → 订阅者（渠道、WebSocket 客户端等）
```

### 5.6 ACP 协议

Agent 之间通过 ACP (Agent Communication Protocol) 通信，支持子 Agent 的创建、监督、结果回收。

```
ACP Client → ACP Server → Session Binding
  源: src/acp/
```

## 6. 关键技术选型

| 决策 | 选择 | 原因 |
|------|------|------|
| 语言 | TypeScript | 可 hackable、社区大、迭代快 |
| 包管理 | pnpm workspace | monorepo 管理、依赖隔离 |
| 构建 | tsdown | 快速构建 |
| 验证 | Zod | 类型安全的 schema 验证 |
| 配置格式 | JSON5 + YAML | 灵活、可注释 |
| 测试 | Vitest | 兼容 Jest API + 快速 |
| 日志 | Pino + 自定义 | 高性能结构化日志 |
| 流式传输 | Server-Sent Events | 实时消息推送 |
| 通信 | WebSocket + HTTP | 双向实时 + RESTful |

## 7. 数据流术语对照

| 源码中的术语 | 含义 |
|-------------|------|
| Inbound Event | 渠道收到的原始消息事件 |
| Turn | 一次消息的处理回合（从收到到回复） |
| Session | 一个对话的持久化上下文 |
| Transcript | 会话的完整历史记录 |
| Compaction | 对历史对话进行摘要压缩 |
| Tool Call | Agent 调用的一个工具 |
| Provider | 大模型提供商 |
| Channel | 消息渠道（Telegram/Discord 等） |
| Plugin | 扩展包（插件） |
| Hook | 插件的生命周期钩子 |
| Skill | 技能（提供给 Agent 的指令集） |
| ACP | 智能体间通信协议 |
| SubAgent | 子智能体（由主 Agent 派生的辅助 Agent） |
| Gateway | 网关服务（主进程） |
| Node | 设备节点（手机/电脑等客户端） |

## 8. 启动流程

```
openclaw.mjs (CLI 入口)
  → 检测 Node 版本
  → gateway-cli.ts (解析 CLI 参数)
  → server-http.ts (HTTP 服务器启动)
      → server-startup-early.ts (早期初始化)
      → server-startup-config.ts (加载配置)
      → server-startup-plugins.ts (加载所有插件)
      → server-startup-memory.ts (初始化记忆系统)
      → server-startup-post-attach.ts (启动完成)
  → server-cron.ts (启动定时任务)
  → server.ts (进入事件循环)
```

## 9. 学习路线建议

按依赖关系由浅入深：

1. **配置系统** (`src/config/`) — 一切的基础，好理解
2. **Gateway 服务** (`src/gateway/`) — 核心服务器，了解请求处理流程
3. **插件系统** (`src/plugins/`) — 理解怎么扩展
4. **信道系统** (`src/channels/`) — 消息从哪来到哪去
5. **Agent 引擎** (`src/agents/`) — 最核心的智能体逻辑
6. **LLM 集成** (`src/agents/provider-*`, `src/agents/embedded-agent-runner.ts`)
7. **工具系统** (`src/agents/agent-tools.ts`, `bash-tools.*`)
8. **ACPC 协议** (`src/acp/`)
9. **安全模型** — 贯穿各层
10. **记忆系统**、**节点管理**、**进程管理** — 外围功能
